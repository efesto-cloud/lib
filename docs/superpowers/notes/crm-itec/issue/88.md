# #88 La forma del contract: input come schemi, IUtente, errori nativi, container nella composition root

Part of #41

Deciso con Dario l'11/11/2026, rileggendo #78. Passo dell'epic dopo #90 (le cartelle) e prima di #73, che costruisce su `Utente` e sul contract.

**Blocked by**: #78 (chiuso, unito).

## Perché

#78 ha dato al contract una forma che non è quella voluta: gli input degli use case sono interfacce TypeScript che nessuno valida, ciò che esce è un `UtenteDto` con suffisso, alcune righe serializzate stanno in `type/`, gli errori passano da un helper con un codec che in produzione nessuno chiama, e il container è un singleton globale del core.

## Cosa

1. **L'input di ogni use case è uno schema zod**, nello **stesso file** dell'interfaccia dello use case nel contract (`useCase/utenti/ICreateUtente.ts`): `export const CreateUtenteInput = z.object(…)` e `export type CreateUtenteInput = z.infer<…>`. Niente suffisso `Dto`. Lo use case nel core usa il tipo ricavato dallo schema.
   - **Il `parse` lo fa chi chiama, al bordo, e solo dove serve**: dove entra un dato grezzo, non ancora validato né tipizzato (il `FormData` di un'action, i parametri di una richiesta, il JSON della sonda). Dove il valore è già validato e tipizzato (per esempio l'utente della sessione in un loader, o una costante del seed) non si rivalida. Lo use case riceve l'input già tipizzato e non lo rivalida.
   - `dto/DatiUtente.ts` diventa uno schema riusato dagli input di creazione e modifica.
2. **Ciò che esce è un'interfaccia `I<Entità>`**, una per entità, in `interface/`: `UtenteDto` → `IUtente`. La cartella `dto/` sparisce. Non sono schemi: li produce il nostro codice, un controllo in runtime non proteggerebbe niente.
3. **`type/` resta per union e struct semplici** (`ProbeState`, `RuoloBu`, `RowsByTable`). Le righe serializzate passano in `interface/`: `SyncLogEntry` → `ISyncLogEntry`, `ProbeStateChange` → `IProbeStateChange`. Il canale della sonda (`sonda/`) resta di schemi: per il Worker è un input.
4. **Gli errori con la forma nativa di better-result**: `class X extends TaggedError("X")<{ campi }>() {}`. Via l'helper `taggedError`, il suo codec, le soppressioni di biome e zod dagli errori. La webapp usa l'errore com'è e distingue per `_tag` (`MESSAGGI`, `match`). Codificare un errore per un mezzo (un'API HTTP, per esempio) è compito di chi lo espone, non del contract: non si scrive finché non serve.
5. **Il container lo crea la composition root**: il core espone solo un install (una funzione che riceve il `Container` e ci carica i moduli degli use case). Via il singleton di `di/container.ts`, il flag `initialized` e l'export default. `sonda/src/index.ts`, `webapp/workers/bootstrap.ts`, `webapp/seed/index.ts` creano il loro `new Container({ defaultScope: "Singleton" })`; `webapp/test/sonda.test.ts` si crea il suo invece di legare stub sul container della webapp.
6. **L'ADR 0009** si aggiorna su questi punti (togliendo la trappola del codec).

## Fatto quando

- Nessun `Dto` nel contract, nessuna cartella `dto/`; ogni use case ha il suo schema d'input nello stesso file, e ogni route che passa a uno use case un dato grezzo lo fa passare dallo schema (un input sbagliato dà 400, con un test).
- Nessun `taggedError`/`codec` nel repo; i messaggi d'errore dell'interfaccia funzionano come prima.
- `@itec/core/di/container` non esporta più un container; ogni composition root ha il suo.
